# セッションの振り返り

現在の作業セッションを分析し、AI 運用ドキュメントの改善提案を生成する。

**このスキルは提案のみを出力する — 変更の自動適用は行わない。** 承認された提案の実行には `maintaining-ai-docs` を使用する。

## 責務の境界

| スキル | 役割 |
|--------|------|
| **wf-08-reflecting-on-sessions** | セッション分析 → 提案生成（提案のみ） |
| `maintaining-ai-docs` | 承認された提案を実際のドキュメント更新として実行 |
| `wf-retrospective` | 作業ログの複数セッション横断的な定量分析 |
| `managing-agent-memory` | セッション横断の知見を永続化（提案先の一つ） |

## プロセス

### コンテキストの収集

本日の変更を収集してセッションの内容を把握する:

```bash
git diff HEAD
git log --oneline --since="$(date +%Y-%m-%d)"
```

### セッションの分析

会話のコンテキストと変更差分を以下の観点で検査する。詳細なチェックリストは [references/analysis-checklist.md](references/analysis-checklist.md) を参照。

1. **新しいツール/コマンド/MCP** — 使用したがまだドキュメント化されていないもの
2. **繰り返し発生した摩擦** — 手順の欠落や曖昧さによる手戻り
3. **合意された慣例** — ユーザーと合意した新ルールでまだ文書化されていないもの
4. **スキルのギャップ** — 適切なスキルが存在しなかった、または既存スキルの指示が不十分だったケース
5. **ドキュメントのギャップ** — 必要な参考資料が利用できなかったケース
6. **自動化可能な繰り返し** — フックで処理できる手動操作
7. **次のセッションへの知見** — 失われるリスクのあるコンテキスト

### 提案の生成

- 最大 **5 件**（ノイズ防止）
- 既にドキュメント化済みの内容はスキップ
- Q&A のみのセッションでアクション可能な発見がない場合は「提案なし」と簡潔な理由を出力して終了

### 出力のフォーマット

[references/output-template.md](references/output-template.md) のテンプレートを使用する。

## ガードレール

- 提案のみ出力 — 変更の自動適用は禁止
- 1 セッションあたり最大 5 件
- ドキュメント化済みの内容はスキップ
- Q&A のみのセッションは「提案なし」で即完了
