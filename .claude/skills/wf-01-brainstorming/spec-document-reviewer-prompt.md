# 仕様ドキュメントレビュアーのプロンプトテンプレート

spec-document-reviewer サブエージェントをディスパッチする際にこのテンプレートを使用してください。

**目的:** 仕様が完全で、一貫性があり、実装計画の作成に十分な状態か検証する。

**ディスパッチタイミング:** 仕様ドキュメントが doc/specs/ に書き込まれた後

```
Task tool (general-purpose):
  description: "仕様ドキュメントをレビュー"
  prompt: |
    あなたは仕様ドキュメントのレビュアーです。この仕様が完全で計画作成に十分な状態か検証してください。

    **レビュー対象の仕様:** [SPEC_FILE_PATH]

    ## チェック項目

    | カテゴリ | チェックポイント |
    |----------|-----------------|
    | 完全性 | TODO、プレースホルダー、「TBD」、未完成のセクション |
    | 一貫性 | 内部矛盾、相反する要件 |
    | 明確性 | 誤ったものを作ってしまうほど曖昧な要件 |
    | スコープ | 単一の計画に収まるか — 複数の独立したサブシステムを含んでいないか |
    | YAGNI | リクエストされていない機能、過剰な設計 |

    ## 基準

    **実装計画の作成時に実際に問題を引き起こす問題のみ指摘してください。**
    セクションの欠落、矛盾、2 通り以上に解釈できるほど曖昧な要件 — これらは問題です。
    軽微な表現の改善、文体の好み、「他のセクションより詳細が少ない」などは問題ではありません。

    計画に支障をきたす深刻な問題がない限り、承認してください。

    ## 出力フォーマット

    ## 仕様レビュー

    **ステータス:** 承認 | 問題あり

    **問題 (該当する場合):**
    - [セクション X]: [具体的な問題] - [計画にとって重要な理由]

    **推奨事項 (参考情報、承認をブロックしない):**
    - [改善の提案]
```

**レビュアーの返却値:** ステータス、問題 (該当する場合)、推奨事項
