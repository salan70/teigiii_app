# 完了前の検証

## 概要

検証なしに作業完了を主張するのは、効率ではなく不誠実である。

**基本原則:** エビデンスが先、主張は後。常に。

**このルールの文言に違反することは、このルールの精神に違反することである。**

## 鉄の掟

```
最新の検証エビデンスなしに完了を主張してはならない
```

このメッセージ内で検証コマンドを実行していなければ、パスしたと主張できない。

## ゲート関数

```
ステータスの主張や満足の表現をする前に:

1. 特定: どのコマンドがこの主張を証明するか？
2. 実行: 完全なコマンドを実行（フレッシュに、完全に）
3. 読む: 出力全体、終了コード、失敗数を確認
4. 検証: 出力が主張を裏付けるか？
   - いいえの場合: エビデンス付きで実際のステータスを述べる
   - はいの場合: エビデンス付きで主張する
5. そこで初めて: 主張する

いずれかのステップを省略 = 検証ではなく嘘
```

## よくある失敗

| 主張 | 必要なもの | 不十分なもの |
|-------|----------|----------------|
| テストがパス | テストコマンド出力: 0 failures | 前回の実行、「パスするはず」 |
| リンターがクリーン | リンター出力: 0 errors | 部分的なチェック、推測 |
| ビルドが成功 | ビルドコマンド: exit 0 | リンターがパス、ログが問題なさそう |
| バグが修正 | 元の症状のテスト: パス | コードを変更した、修正されたはず |
| リグレッションテストが機能 | Red-Green サイクルの検証 | テストが1回パス |
| エージェントが完了 | VCS diff が変更を表示 | エージェントが「成功」と報告 |
| 要件を満たす | 行ごとのチェックリスト | テストがパスしている |

## 危険信号 - 止まる

- 「はず」「たぶん」「のようだ」を使っている
- 検証前に満足を表現（「よし！」「完璧！」「完了！」等）
- 検証なしにコミット/プッシュ/PR しようとしている
- エージェントの成功報告を信用している
- 部分的な検証に頼っている
- 「今回だけ」と思っている
- 疲れていて作業を終わらせたい
- **検証を実行せずに成功を示唆するいかなる表現**

## 合理化の防止

| 言い訳 | 現実 |
|--------|---------|
| 「今はうまくいくはず」 | 検証を実行する |
| 「自信がある」 | 自信 ≠ エビデンス |
| 「今回だけ」 | 例外なし |
| 「リンターがパスした」 | リンター ≠ コンパイラ |
| 「エージェントが成功と報告」 | 独立して検証する |
| 「疲れている」 | 疲労 ≠ 免罪符 |
| 「部分的なチェックで十分」 | 部分的は何も証明しない |
| 「違う表現だからルール適用外」 | 文言より精神 |

## 主要パターン

**テスト:**
```
✅ [テストコマンド実行] [表示: 34/34 pass] 「すべてのテストがパス」
❌ 「今はパスするはず」 / 「正しそう」
```

**リグレッションテスト（TDD Red-Green）:**
```
✅ 書く → 実行（パス） → 修正を戻す → 実行（必ず失敗） → 復元 → 実行（パス）
❌ 「リグレッションテストを書いた」（Red-Green 検証なし）
```

**ビルド:**
```
✅ [ビルド実行] [表示: exit 0] 「ビルドがパス」
❌ 「リンターがパスした」（リンターはコンパイルをチェックしない）
```

**要件:**
```
✅ 計画を再読 → チェックリスト作成 → 各項目を検証 → 不足や完了を報告
❌ 「テストがパスしたのでフェーズ完了」
```

**エージェント委譲:**
```
✅ エージェントが成功報告 → VCS diff 確認 → 変更を検証 → 実際の状態を報告
❌ エージェント報告を信用
```

## なぜ重要か

24件の失敗記録から:
- 人間のパートナーが「信じない」と言った — 信頼が壊れた
- 未定義の関数が出荷された — クラッシュするはずだった
- 欠落した要件が出荷された — 不完全な機能
- 偽の完了報告に費やされた時間 → 差し戻し → やり直し
- 違反: 「正直は中核的価値観。嘘をつけば、交代させられる。」

## いつ適用するか

**常に、以下の前に:**
- 成功/完了を主張するいかなるバリエーション
- 満足のいかなる表現
- 作業状態に関するいかなるポジティブな発言
- コミット、PR 作成、タスク完了
- 次のタスクへの移行
- エージェントへの委譲

**ルールの適用対象:**
- 正確な表現
- 言い換えや同義語
- 成功の暗示
- 完了/正確性を示唆するいかなるコミュニケーション

## 結論

**検証にショートカットはない。**

コマンドを実行する。出力を読む。そして結果を主張する。

これは交渉の余地がない。
