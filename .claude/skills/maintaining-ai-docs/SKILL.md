# AI ドキュメントの保守

AI 運用ドキュメントを実践的で具体的な内容に保ちつつ、変更を最小限に抑える。

## 基本原則

- **What だけでなく How を。** すべてのルールには実行手順、判断基準、コマンドを含める。方針の宣言だけでは不十分。
- **少ないほど良い。** 変更行数を最小化する。重複を避け、既存コンテンツを再掲せず参照する。
- **差分は最小に。** 変更目的に直接関係する行だけを編集する。フォーマットの整理をコンテンツ変更と混ぜない。定量基準と例は [references/diff-strategy.md](references/diff-strategy.md) を参照。

## 対象ファイル

- ルート運用ファイル: `AGENTS.md`、`CLAUDE.md`
- スキル定義: `*/skills/*/SKILL.md`
- 補足リファレンス: `references/*.md`

## 更新ワークフロー（デフォルト）

AI ドキュメントの作成・更新を依頼された場合のデフォルトモード。

**変更目的を一文で確定する。** ファイルに触れる前に行う。

**既存コンテンツを読み**、変更が必要な行だけを特定する。正しい箇所は書き直さない。

**How を追加する** — 手順の順序、実行コマンド（該当する場合）、例外処理の分岐を含める。

**冗長さを削る** — 同義の言い換え、既存コンテンツとの重複、長い背景説明を除去する。

**差分を検証する:**
- 記載した目的の範囲外の行が変更されていないこと
- `.agents/skills/` は `.claude/skills/` へのシンボリックリンクである — 正本は `.claude/skills/` のみ編集する

## 品質監査ワークフロー

「品質チェック」「監査」「スコアリング」「ドキュメント品質」を含むリクエストで発動する。

**調査:** 対象ファイルを特定する。指定がなければ `CLAUDE.md`、`AGENTS.md`、`*/skills/*/SKILL.md` をスキャンする。

**評価:** 各ファイルを [references/quality-criteria.md](references/quality-criteria.md) の 6 基準で採点する。

**レポート:** 更新提案の前に品質レポートを提示する:

```
## 品質レポート

### サマリー
- 評価ファイル数: X
- 平均スコア: X/100
- 要更新ファイル数: X

### ファイル別評価

#### 1. ./CLAUDE.md
**スコア: XX/100（グレード: X）**

| 基準 | スコア | メモ |
|------|--------|------|
| コマンド＆ワークフロー | X/20 | ... |
| 構造の明確さ | X/20 | ... |
| 非自明なパターン | X/15 | ... |
| 簡潔さ | X/15 | ... |
| 鮮度 | X/15 | ... |
| 実行可能性 | X/15 | ... |

**問題点:**
- [具体的な問題]

**改善案:**
- [具体的な追加・修正]
```

**更新を提案する:** ユーザーの承認後、上記の更新ワークフローで改善を適用する。

## 最小差分の例

```text
良い例: 説明に 1 行追加（変更 1 行、範囲: メタデータのみ）
  description: 既存のテキスト。新しいトリガーフレーズを追加

悪い例: 説明の変更と本文のリフォーマットを同時に行う（変更 15 行、範囲: ファイル全体）
  -> 意図した変更に無関係な差分が混入
```

## 完了前チェックリスト

- [ ] すべてのルールに How（手順、コマンド、例外）が含まれている
- [ ] コマンドはコピー＆ペーストで実行可能な形式
- [ ] 例外処理が明示されている
- [ ] 不要な説明が残っていない
- [ ] `.claude/skills/` の正本のみ編集した（`.agents/skills/` シンボリックリンクではない）
