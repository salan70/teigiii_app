# ワークフロースキルの使い方

このスキルは、ユーザーの依頼に対して適切なワークフロースキルを自動的に選択・実行するルーターです。

## 指示の優先順位

1. **ユーザーの指示**（最優先） — 会話内での直接的な指示
2. **Skills** — Skill ツール経由で呼び出された場合
3. **CLAUDE.md のデフォルト**（最低） — CLAUDE.md に記載されたルール

## 絶対ルール: スキルを使え

**依頼内容に 1% でも該当するスキルがあれば、必ず Skill ツールで呼び出すこと。**

スキルを呼び出さずに直接作業を始めることは禁止。スキルには、品質・一貫性・安全性を担保するプロセスが組み込まれている。

## 合理化の禁止

以下の理由でスキルの呼び出しを省略してはならない:

| アンチパターン | なぜダメか |
|---|---|
| 「単純だからスキル不要」 | 単純なタスクこそ検討不足の前提が多い |
| 「時間がかかるから直接やる」 | スキルのプロセスが手戻りを防ぐ |
| 「前回と同じだからスキップ」 | 文脈が変わっている可能性がある |
| 「ユーザーが急いでいるから省略」 | ユーザーが明示的に省略を指示した場合のみ例外 |
| 「自分で判断できるから不要」 | スキルはプロセスの一貫性を保証する |

## スキル優先順位

1. **プロセススキル（wf-xx）** — ワークフローの流れを制御するスキルを最優先
2. **実装スキル** — 具体的な作業を行うスキル（TDD、デバッグ等）

プロセススキルが実装スキルを内部で呼び出すため、プロセススキルから始めること。

## wf スキル一覧とトリガー条件

| スキル | トリガー条件 |
|---|---|
| `wf-01-brainstorming` | すべてのタスクの開始時（「brainstorming 不要」と明示された場合を除く） |
| `wf-02-using-git-worktrees` | 隔離が必要な機能開発の開始時 |
| `wf-03-writing-plans` | 仕様・設計が承認された後、実装計画を作成する時 |
| `wf-04-executing-plans` | 作成済みの実装計画を別セッションで実行する時 |
| `wf-04-subagent-driven-development` | 現セッション内で独立タスクを並列実行する時 |
| `wf-05-requesting-code-review` | タスク完了時・主要機能実装後のレビュー依頼時 |
| `wf-06-verification-before-completion` | 作業完了を主張する前の検証時 |
| `wf-07-finishing-a-development-branch` | 実装完了後の統合方法決定時 |
| `wf-08-reflecting-on-sessions` | セッション振り返り時 |

## 基本フロー（自動チェーン）

```
wf-01-brainstorming
  └→ wf-03-writing-plans
       └→ wf-04-subagent-driven-development / wf-04-executing-plans
            └→ wf-06-verification-before-completion
                 └→ wf-07-finishing-a-development-branch
```

各スキルの末尾に次のスキルへのチェーン指示がある。**チェーンは必ず Skill ツールを使って実行すること。** 手動で次のスキルの内容を再現してはならない。

## チェーンの実行方法

スキルが「次は wf-XX を呼び出す」と指示している場合:

1. 現在のスキルの作業を完了する
2. **Skill ツール**を使って次のスキルを invoke する
3. スキルの内容を自分で再現しない — 必ず Skill ツール経由で呼び出す

## 補助スキル（wf-common-xx）

| スキル | 自動呼び出し条件 |
|---|---|
| `wf-common-git-operations` | コミット、ブランチ作成、機密ファイルチェック時 |
| `wf-common-collaborating-on-github` | GitHub Issue、PR、コメント操作時 |
| `wf-common-test-driven-development` | TDD・テストファースト開発時 |

## 対応スキル（レビュー受領）

| スキル | 自動呼び出し条件 |
|---|---|
| `receiving-code-review` | PR レビュー指摘への対応時・レビューコメントを受けて修正する時 |

**トリガーフレーズ例:** 「レビュー指摘対応」「指摘をもらいました」「レビューコメント対応」「指摘に対応して」「レビューの修正」「PR にコメントが来た」「レビュー対応お願い」
