# 開発ブランチの完了

## 概要

明確なオプションを提示し、選択されたワークフローを実行することで、開発作業の完了をガイドします。

**基本原則:** テスト検証 → オプション提示 → 選択の実行 → クリーンアップ。

**開始時に宣言:** 「wf-07-finishing-a-development-branch スキルを使ってこの作業を完了します。」

## プロセス

### Step 1: テストの検証

**前提:** `wf-06-verification-before-completion` スキルの手順に従い、lint・テスト・セルフレビューを完了させること。

**オプション提示前にテストが通ることを確認:**

```bash
# プロジェクトのテストスイートを実行
npm test / cargo test / pytest / go test ./...
```

**テストが失敗した場合:**
```
テスト失敗 (<N> 件の失敗)。完了前に修正が必要です:

[失敗内容を表示]

テストが通るまでマージ/PR に進めません。
```

ここで停止。Step 2 に進まない。

**テストが通った場合:** Step 2 に進む。

### Step 2: ベースブランチの特定

```bash
# 一般的なベースブランチを試す
git merge-base HEAD main 2>/dev/null || git merge-base HEAD master 2>/dev/null
```

または確認: 「このブランチは main から分岐しました — 合っていますか？」

### Step 3: オプションの提示

以下の 4 つのオプションを正確に提示:

```
実装が完了しました。どうしますか？

1. <base-branch> にローカルでマージ
2. プッシュして Pull Request を作成
3. ブランチをそのまま残す（後で対応する）
4. この作業を破棄する

どのオプションにしますか？
```

**説明を加えない** — オプションは簡潔に。

### Step 4: 選択の実行

#### オプション 1: ローカルマージ

```bash
# ベースブランチに切り替え
git checkout <base-branch>

# 最新を取得
git pull

# フィーチャーブランチをマージ
git merge <feature-branch>

# マージ結果のテストを検証
<test command>

# テストが通った場合
git branch -d <feature-branch>
```

その後: Worktree のクリーンアップ (Step 5)

#### オプション 2: プッシュして PR 作成

```bash
# ブランチをプッシュ
git push -u origin <feature-branch>

# PR を作成
gh pr create --title "<title>" --body "$(cat <<'EOF'
## 概要
<変更内容を 2〜3 項目で>

## テスト計画
- [ ] <検証ステップ>
EOF
)"
```

その後: Worktree のクリーンアップ (Step 5)

#### オプション 3: そのまま残す

報告: 「ブランチ <name> をそのまま残します。Worktree は <path> に保持されます。」

**Worktree のクリーンアップはしない。**

#### オプション 4: 破棄

**まず確認:**
```
以下が完全に削除されます:
- ブランチ <name>
- すべてのコミット: <commit-list>
- Worktree: <path>

確認するには 'discard' と入力してください。
```

正確な確認を待つ。

確認された場合:
```bash
git checkout <base-branch>
git branch -D <feature-branch>
```

その後: Worktree のクリーンアップ (Step 5)

### Step 5: Worktree のクリーンアップ

**オプション 1、2、4 の場合:**

worktree 内にいるか確認:
```bash
git worktree list | grep $(git branch --show-current)
```

該当する場合:
```bash
git worktree remove <worktree-path>
```

**オプション 3 の場合:** worktree を維持。

### Step 6: セッションの振り返り

ブランチの作業が完了したら（オプション 1, 2, 4）、`wf-08-reflecting-on-sessions` スキルを呼び出してセッションの振り返りを行う。

> 「作業が完了しました。セッションの振り返りを行います。」

## クイックリファレンス

| オプション | マージ | プッシュ | Worktree 維持 | ブランチ削除 |
|-----------|--------|---------|--------------|-------------|
| 1. ローカルマージ | o | - | - | o |
| 2. PR 作成 | - | o | o | - |
| 3. そのまま残す | - | - | o | - |
| 4. 破棄 | - | - | - | o (強制) |

## よくあるミス

**テスト検証のスキップ**
- **問題:** 壊れたコードをマージ、失敗する PR を作成
- **対策:** オプション提示前に必ずテストを検証

**オープンエンドな質問**
- **問題:** 「次にどうしますか？」→ 曖昧
- **対策:** 構造化された 4 つのオプションを正確に提示

**Worktree の自動クリーンアップ**
- **問題:** 必要な場合に worktree を削除（オプション 2、3）
- **対策:** クリーンアップはオプション 1 と 4 のみ

**破棄時の確認なし**
- **問題:** 誤って作業を削除
- **対策:** 'discard' のタイプ入力による確認を必須化

## 危険信号

**絶対にしないこと:**
- テスト失敗のまま続行
- マージ結果のテスト検証なしにマージ
- 確認なしに作業を削除
- 明示的な要求なしに force-push

**必ず行うこと:**
- オプション提示前にテストを検証
- 正確に 4 つのオプションを提示
- オプション 4 でタイプ入力による確認を取得
- オプション 1 と 4 のみ worktree をクリーンアップ
