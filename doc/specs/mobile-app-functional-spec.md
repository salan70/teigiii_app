# モバイルアプリ機能仕様

## 1. 位置づけ

本書はモバイルアプリの画面状態、操作、遷移、失敗時の挙動を定義する継続的な正本である。

- 画面マップ、ナビゲーション、Tier 境界は `mobile-app-information-architecture.md` を正とする
- API の契約は `workers-api-server.md` と OpenAPI を正とする
- 実装順序と検証手順は `doc/plans/` の計画を正とする
- Tier 1 完了後もファイル名を変えず、機能追加時に本書を更新する

## 2. 共通 UI

### 2.1 ビジュアル基盤

- Material 2 を使用する。`useMaterial3` は `false` を維持する
- 既存の緑系 ColorScheme と LINESeedJP を使用する
- ライトテーマとダークテーマの両方を提供する
- タップ対象は 44 pt 相当以上を確保し、文字拡大時に主要操作が欠けないようにする
- loading、empty、error、data の各状態を画面ごとに明示する

### 2.2 最上位ナビゲーション

下部ナビゲーションを次の順序で固定する。

1. あなたの辞書
2. みんなの辞書
3. タイムライン

- cold start 時は常に「あなたの辞書」を選択する
- バックグラウンド復帰では現在のタブを維持する
- 選択中のタブを再度タップした場合は、そのタブのルートへ戻して先頭までスクロールする
- 各タブは独立した navigation stack を持つ

### 2.3 共通ヘッダー

- すべての最上位画面にグローバル検索を置く
- 「あなたの辞書」にだけアバターを置き、アカウントメニューへ遷移する
- Tier 1 では通知ベルを置かない

## 3. 定義の作成

### 3.1 入口

- あなたの辞書: `定義を書く` の拡張 FAB
- タイムライン: 両タブに `定義を書く` の拡張 FAB
- 言葉ページ: `この言葉を定義する` ボタン
- みんなの辞書: `言葉を登録` ボタン。登録完了後に定義作成を選べる
- 公開プロフィールと定義詳細には汎用作成 FAB を置かない

### 3.2 汎用作成画面

「あなたの辞書」またはタイムラインから開いた場合は、言葉、よみ、本文を 1 画面で入力する。事前検索を必須にしない。

- 初期フォーカスは言葉
- 入力順は言葉、よみ、本文
- 言葉は 30 文字、よみは 50 文字、本文は 500 文字まで
- 公開範囲は上部の `全体に公開`／`非公開` セレクターで選ぶ
- 初期値は `全体に公開`
- 主操作は `投稿`、補助操作は `下書きを保存`

### 3.3 言葉ページ起点

- 対象の `word_id` を Draft に保持する
- 言葉とよみは表示するが編集不可とする
- 初期フォーカスは本文

### 3.4 確定

- 言葉、よみ、本文がすべて有効な場合だけ確定できる
- Draft 起点では `POST /v1/definition-drafts/{id}/finalize` を使用する
- Draft が未作成のまま投稿された場合も、クライアントで Draft ID を生成して保存・確定する
- 確定処理は同じ Draft ID で再試行しても定義を重複作成しない
- 成功後は作成した定義詳細へ遷移する

### 3.5 既存語との競合

- 同一表記かつ同一よみ: 確認なしで既存語へ紐付ける
- 同一表記かつ異なるよみ: 既存語の表記・よみを表示し、既存語へ追加するか確認する
- 確認をキャンセルした場合は入力画面へ戻し、Draft を維持する
- 新規語は定義確定時に初めて共有言葉として登録する

## 4. 下書き

### 4.1 データモデル

下書きは `definitions.status` ではなく `definition_drafts` として保持する。

- ID はクライアント生成 UUID
- ユーザー ID は必須
- `word_id` は任意。言葉ページ起点または既存語へ解決済みの場合に保持する
- 入力中の言葉、よみ、本文はそれぞれ空を許容する
- 公開範囲の選択状態を保持する
- 作成日時と更新日時を保持する
- 下書きは本人以外から取得できない

### 4.2 保存 API

- `PUT /v1/definition-drafts/{id}` で作成と更新を冪等に処理する
- 全項目空の新規 Draft は送信しない
- `GET /v1/me/definition-drafts` は更新日時降順で cursor pagination する
- `GET /v1/definition-drafts/{id}` は本人だけ取得できる
- `DELETE /v1/definition-drafts/{id}` は冪等に削除する
- 確定 API は必須項目検証、言葉解決、定義作成、Draft 完了をサーバーで一貫して処理する

### 4.3 自動保存

- 作成画面から離れる時とアプリがバックグラウンドへ移る時に保存する
- 入力中の定期保存は行わない
- 明示的な `下書きを保存` を提供する
- 離脱時は保存完了を待ってから画面を閉じる
- 離脱時に保存が失敗した場合は画面を維持し、`再試行` と `変更を破棄` を表示する
- バックグラウンド保存失敗は未同期状態としてメモリ保持し、復帰時に通知して再試行する
- 未同期 Draft のローカル永続化は行わない

### 4.4 空の下書き

- 全項目空の新規画面は何も作らず終了する
- 既存 Draft を全項目空にして離脱する場合は削除確認を表示する
- 削除確認をキャンセルした場合は編集画面へ戻る

### 4.5 複数 Draft

- 同じ言葉に複数 Draft を作成できる
- 同じ表記の既存 Draft がある場合は作成画面内に非 blocking の案内と一覧へのリンクを表示する
- 新規作成自体は妨げない

## 5. 定義の編集と状態変更

- 確定後は言葉とよみを変更できない
- 本文編集は `editable_until` まで許可する。端末時計ではなく API 応答を正とする
- 期限後に編集画面を開かず、新しい定義を書く導線を表示する
- 新しい定義の本文へ過去の本文を自動複製しない
- 公開／非公開は期限後も切り替え可能で、編集期限を延長しない
- 確定済み定義を Draft へ戻せない
- 削除は確認後に実行し、成功後は一覧、言葉ページ、タイムラインを再取得する

## 6. あなたの辞書

### 6.1 data 状態

- 定義済みの言葉数
- 下書き数
- 保存した言葉数
- 最近更新した確定済み定義
- `定義を書く` の拡張 FAB

各件数から対応する一覧へ遷移する。最近の定義から定義詳細へ遷移する。

### 6.2 empty 状態

- 通常の空リストを表示しない
- 辞書の目的を短く説明する
- `最初の定義を書く` を主操作として、汎用作成画面へ遷移する
- 事前の言葉検索欄は置かない

### 6.3 定義済みの言葉

- 言葉単位でまとめ、読み順で表示する
- 公開件数と非公開件数を表示する
- Draft は専用一覧へ分離し、定義済み件数へ含めない
- タップで言葉ページへ遷移する

### 6.4 下書き一覧

- 更新日時降順
- 言葉があれば言葉を主表示する
- 言葉が空で本文があれば本文先頭を主表示する
- 言葉と本文が空ならよみを主表示する
- タップで編集を再開する
- 削除操作は確認後に実行する

### 6.5 保存した言葉

- 保存日時降順
- 自分が定義済みかを表示する
- タップで言葉ページへ遷移する

## 7. みんなの辞書

- 全言葉を読み順の単一連続リストで表示する
- 読み見出し（あ、い、う等）を取得済みデータから挿入する
- 五十音の中間ページとジャンプ UI は作らない
- `すべて`、`定義あり`、`定義なし` で絞り込む
- 画面内検索は入力停止から約 300 ms 後に適用する
- 検索文字列が空になった場合は元の一覧へ戻す
- filter または検索文字列変更時は cursor を破棄して先頭から取得する
- loading、empty、error は一覧領域内に表示し、ヘッダー操作は維持する

### 7.1 言葉の登録

- 表記とよみを入力する
- 入力中に重複候補を表示する
- 既存語を選んだ場合はその言葉ページへ遷移できる
- 新規登録後は `続けて定義を書く` と `完了` を表示する
- 明示的な言葉登録は定義を伴わなくても即時に共有言葉へ追加する

## 8. 言葉ページ

- 表記、よみ、保存状態を表示する
- `この言葉を定義する` を主操作とする
- 自分の定義を他者の定義より先に表示する
- 自分の確定済み定義は更新日時降順で 3 件まで表示し、残りは `すべて見る` へ送る
- この `word_id` を持つ Draft を分離表示し、編集を再開できる
- 他者の公開定義だけを `新着順`／`リアクション順` で表示する
- 自分の定義を他者一覧へ重複表示しない
- 保存／保存解除は冪等に処理し、失敗時は表示状態を元へ戻す
- 言葉の修正可否は API の `isEditableByMe` を正とする
- 修正不可の場合は外部通報フォームへの導線を表示する

## 9. タイムライン

### 9.1 タブ状態

- 初回は `見つける`
- 2 回目以降は最後に開いていたタブを端末内へ保存して復元する
- 両タブに `定義を書く` の拡張 FAB を置く

### 9.2 見つける

- 公開定義と新規言葉登録を完全な新着順で混在表示する
- 集約、スコアリング、連続表示抑制を行わない
- 定義は定義詳細へ、言葉登録は言葉ページへ遷移する
- 言葉登録者を表示しない

### 9.3 フォロー中

- フォロー対象者の公開定義だけを完全な新着順で表示する
- 自分の定義、下書き、非公開定義、言葉登録を表示しない
- ミュート対象を表示しない

## 10. グローバル検索

- 最上位画面の検索アイコンから同じ検索画面を開く
- 入力中は API を呼ばず、検索ボタンまたはキーボードの検索操作で確定する
- 空文字では検索しない
- 検索確定後は `言葉` と `ユーザー` の 2 タブを表示する
- 初期タブは `言葉`
- タブ切り替え後も検索文字列を維持する
- 言葉は表記・よみ、ユーザーは表示名・公開ユーザー ID の部分一致
- 各タブは独立した cursor と loading／empty／error 状態を持つ
- 定義本文検索は Tier 2 まで表示しない

## 11. 定義詳細

- 言葉、よみ、本文、投稿者、投稿日時、編集済み表示、リアクションを表示する
- 本人にだけ公開状態と編集／公開範囲変更／削除を表示する
- 他者の定義では投稿者プロフィール、フォロー、ミュート、通報へ遷移できる
- 言葉部分をタップすると言葉ページへ遷移する
- 汎用の定義作成 FAB は置かない
- いいねの付与／解除と件数、いいねしたユーザー一覧を維持する

## 12. 公開プロフィール

- アバター、表示名、自己紹介、公開定義数、フォロー数、フォロワー数を表示する
- 他者ではフォロー操作とミュート／通報メニューを表示する
- 公開辞書は言葉単位で読み順表示し、言葉ごとの公開定義数を示す
- `いいねした投稿` はプロフィール内リンクから独立一覧へ遷移する
- 自分・他ユーザーのどちらからも、そのユーザーがいいねした公開定義を表示できる
- 獲得リアクション総数、人気順位、平均リアクション数は表示しない

## 13. 通報

Tier 1 は外部フォームを使う。

- 対象種別: `user`、`definition`、`word`
- 対象 ID、報告者の公開ユーザー ID、理由をフォームへ事前入力する
- ユーザー通報はプロフィールと定義詳細のユーザーメニューから開く
- 定義通報は定義詳細から開く
- 言葉通報は言葉ページから開く
- 送信は外部フォームで行い、アプリ内 reports テーブルと履歴画面は作らない

## 14. 初回利用

- 初回案内は 1 画面
- 既存の規約・プライバシーポリシーへの導線と同意確認を維持する
- 主文言は「言葉を、自分の言葉で残す辞書です」
- 同意後は匿名認証済みの「あなたの辞書」へ遷移する
- 初回の定義作成時に、公開／非公開と下書き保存を画面内で簡潔に説明する

## 15. エラーと再試行

- 初回取得失敗: 画面内にエラーと再試行を表示する
- 追加取得失敗: 取得済み内容を維持し、一覧末尾から再試行できるようにする
- 更新失敗: 元の表示状態を維持し、SnackBar または Dialog で再試行可能にする
- 認証エラーと App Check エラーは共通 API 層の処理を使用する
- 404 は削除済みまたは閲覧不可として、存在を推測できる詳細を表示しない

## 16. 検証対象

- backend: Draft API、確定の冪等性、競合、権限、pagination の worker test
- mobile application/repository: DTO 変換、状態遷移、保存失敗、invalidate の unit test
- Widget: navigation、loading／empty／data／error、主要操作の widget test
- iOS: ライト／ダーク、文字拡大、主要画面、作成・Draft・確定・削除の実画面確認
- Android のビルド、画面確認、配信は #187 の完了条件に含めない
