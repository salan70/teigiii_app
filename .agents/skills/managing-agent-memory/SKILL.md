# エージェントメモリの管理

`memories/` ディレクトリを使用して、セッション横断で作業知識を永続化・取得する。

## メモリの保存

### ディレクトリ構成

タスクまたはトピック名で整理する:

```text
memories/
  issue-123/
    2026-01-01-investigation-results.md
  feature-auth/
    requirements.md
    tech-selection.md
```

### ファイルの作成

1. タスクまたはトピック名のディレクトリを作成
2. 日付固有のエントリには `YYYY-MM-DD-summary.md` 形式、常設コンテンツには説明的な名前を使用
3. フロントマターに必ず `summary:` を含める（検索で使用される）

### ファイルフォーマット

```yaml
---
summary: "簡潔な概要（検索時に表示される）"
created: YYYY-MM-DD
tags:
  - investigation
  - bug-fix
---
# 詳細内容

## 発見事項
- ...

## 決定事項
- ...

## 次のアクション
- ...
```

## メモリの呼び出し（段階的開示）

コンテキストを段階的に効率よくロードする — 一度にすべて読み込まない。

**ステージ 1: サマリーのスキャン**

```bash
rg "^summary:" memories/ -A 1
```

**ステージ 2: 該当ファイルのみ読み込み**

サマリーのスキャン結果に基づき、ユーザーのクエリに合致するファイルのみを Read ツールで読み込む。

**ステージ 3: 曖昧な場合はユーザーに確認**

複数の候補が該当する場合、どのメモリを復元するかユーザーに尋ねる。

## 使用例

**調査結果の記録:**
```
ユーザー: 「Issue #123 の調査結果を覚えておいて」
-> memories/issue-123/2026-02-08-investigation-results.md を作成
```

**前回の作業の再開:**
```
ユーザー: 「昨日何をやっていた？」
-> rg でサマリーをスキャン、該当ファイルを読み込み、コンテキストを提示
```

**設計判断の保存:**
```
ユーザー: 「認証の技術選定メモを保存して」
-> memories/feature-auth/tech-selection.md を作成
```

## 重要な注意事項

- `memories/` は `.gitignore` に含まれている（プライベートなメモリ空間）
- 古くなったメモリはノイズ削減のため削除する
- 他のスキルと連携して動作する（振り返り時にここへの知見保存を提案される場合がある）
